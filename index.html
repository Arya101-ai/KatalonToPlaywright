Datepicker: the Katalon custom keyword Manual_datepicker became a reusable DatePicker component. It follows the same path recorded in the LambdaTest log: days header, months header, decade view, year, month, day. If the click does not open the picker, it falls back to jQuery datepicker('show'), like the original keyword.

When things break

The demo site broke. The test got a fix, not a skip.

On 18 Nov 2026 the File Upload page stopped rendering. Here is what failed and what changed.

Why: cdn.guru99.com was unreachable, so the page's render-blocking jQuery never loaded and the upload form never appeared.

Fix in pages/guru99/FileUploadPage.ts
await page.route(/cdn\.guru99\.com/, (route) => /jquery\.min\.js/.test(route.request().url()) ? route.continue({ url: jqueryFallbackUrl }) : route.abort());
passed · 6s

Same jQuery library, served from code.jquery.com. Turn it off with GURU99_CDN_FALLBACK=false once the site recovers.

Presenter notes

Be honest about failures: during the migration, the third-party demo site's CDN went down. The test did not get skipped or marked flaky. The page object routes the jQuery request to code.jquery.com and drops ad and tracker requests so the page's own form loads.

The workaround is a config switch, so it can be removed when the site recovers. This is the kind of thing Playwright network routing makes easy.

Sources: pages/guru99/FileUploadPage.ts (comment: "cdn.guru99.com ... was found unreachable on 2026-11-18, leaving the upload form un-rendered"); config/variables.ts (workarounds.guru99CdnFallback, jquery-1.12.4.min.js); migration-report.html (File Upload passed, 6s). Questions

What TCS will probably ask.

Type to filter. Every answer comes from this migration.

Do the test names stay the same?

Yes. All 6 tests kept their original names, including data-driven names such as "TC_CURA_Login_Parameterization - John Doe" and "TC_CURA_DynamicXPath - Medicaid".

What happens to custom keywords?

They become reusable components. The Manual_datepicker keyword is now pages/components/DatePicker.ts, with the same jQuery fallback the keyword used.

What happens to the Object Repository?

It becomes page objects under pages/. Locators are kept exactly as recorded in the LambdaTest command logs (XPath), so reviewers can compare one to one.

Where do profiles and data files go?

Execution profile values move to config/variables.ts. Test inputs move to JSON files under test-data/, and data-driven tests loop over them.

Can it run on a local browser?

This project is LambdaTest only by design: the fixture stops if LT_USERNAME and LT_ACCESS_KEY are not set. A local Playwright project can be added if you want one.

Which language and Playwright version?

TypeScript, @playwright/test 1.65.1, with a typecheck script (tsc --noEmit).

How was the result verified?

Both suites ran on LambdaTest on the same browser and OS, Chrome 157 on Windows 11: Katalon in build 112382179, Playwright in build 112384971. 6 of 6 passed.

Are retries hiding flaky tests?

No. retries is set to 0 in playwright.config.ts. Traces and screenshots are kept only on failure.

Did any test need a workaround?

Two. The guru99 page's CDN was down on 18 Nov 2026, so jQuery is routed to code.jquery.com behind a switch. The CURA radio buttons get a JS click if a native click leaves them unchecked, which the Katalon runs also needed.

How long did conversion take?

13m 07s for all 6 tests, converted and verified. Tests were converted in parallel, so per-test times overlap.
